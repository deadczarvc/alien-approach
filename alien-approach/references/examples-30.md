# ПРИМЕРЫ — 30 обычных методов (человеческий подход, первый эшелон)

Пример корпуса первого эшелона — MCP-серверы ∧ сервисы агентного контура; для своего домена замените своими 30 методами, структура та же. Иноземный Подход применяется только ПОСЛЕ исчерпания этого списка (SKILL.md, анти-триггер).

## Диагностика живости
1. `<client> mcp test <name>` — штатная проба клиента: соединение + счётчик обнаруженных тулов.
2. Порт-чек (netstat LISTENING) — до всяких выводов о «сервере».
3. Функциональный эндпоинт вместо `/health` — порт UP + health 200 + тишина на рабочем вызове = клин («health врёт»).
4. Живой tool-call как оракул — handshake и exit 0 ≠ работающий тул.
5. Лог-сигнатуры парковки (напр. `ConnectError` в логе агента) + cooldown после неудачи (не долбить `/reload-mcp`).
6. Триада «test жив + прямой spawn жив + боевой мёртв» = баг в предикате ядра, не в конфиге.

## Восстановление и жизненный цикл
7. `/reload-mcp` после смены конфига — parked → reconnect; сервер держит старый конфиг в памяти.
8. Точечный рестарт: только упавший сервис (kill по PID без tree-kill + штатный стартёр).
9. Событийный revive через demand-hook (on_session_start / pre_tool_call) — не таймер.
10. Crash-loop детект по сигнатуре (exit-код, счётчик рестартов) + готовый рецепт, не слепые ретраи.
11. Порядок подъёма снизу вверх: engine → БД → сервер; сервис снаружи job-объекта (иначе умрёт с вызовом).
12. Граница применения правок: правка на диске ≠ фикс в рантайме; статус `pending_runtime_adoption` до рестарта держателя.

## Конфигурация и регистрация
13. Provenance-матрица: main config + каждый профиль отдельно (worker-профили не наследуют MCP).
14. Мультиисточниковый синк: `.claude.json`, `.codex/config.toml`, cursor — union по имени, богатейшая конфигурация побеждает.
15. Readiness-гейт перед добавлением: бинарник есть, порт достижим, env-ключи на месте, дублей нет.
16. Секреты только `${VAR}` из `.env` — литеральный ключ в config.yaml = дефект.
17. Транспорт-нормализация: 405 на probe = старый SSE → `transport: sse`.
18. `lazy: true` для тяжёлых/удалённых серверов.
19. Правка конфига точечным текстовым edit / ruamel — никогда `yaml.safe_dump` всего файла.
20. Верификация патча: YAML-валидация + per-server test + семантический аудит диффа против бэкапа.

## Пути, среда, ключи
21. Path-sweep после wipe смежного дерева: мёртвые пути по ВСЕМ живым конфигам → канонический путь → per-server verify.
22. Форвард-слэши в путях конфига.
23. Полное окружение для subprocess (reqwest требует WINDIR и системные переменные).
24. Ключ проверяется во всех трёх местах (`.env` / HKCU / литерал) — мёртвый HKCU тенит живой `.env`.

## Протокол и потребители
25. mcpc-цепочка: reuse live session → bounded grep → `tools-get` схемы → typed JSON call → парс `isError`/`_mcpc`.
26. Обратный consumer-audit: от живого сервиса к потребителям (кто настроен, denylist-семантика).
27. Docker-живость по healthcheck-циклам (`exec_die`, `docker events`), не по `logs --since` (clock-skew врёт).
28. Warning неиспользуемой интеграции = шум-класс: чинить в источнике (`enabled: false`).

## Инцидент-менеджмент
29. Каждый новый root cause → паттерн-каталог (симптом → корень → фикс → верификация).
30. Слоевой RCA с инструментированием границ + разбор «5-почему» по факту, не по памяти.
